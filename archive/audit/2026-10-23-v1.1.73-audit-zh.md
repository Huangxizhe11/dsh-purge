## 一、结论

无木马、无窃密、无混淆载荷，但**性质上是"拆安全门"工具**：它在你的本机
Disable 掉 harness 的沙箱、审批、hook deny，然后注入一份 25 KB 的系统提示覆盖默认人格。
装上它之后，这个实例的权限边界基本不复存在。

## 三、关键发现

### 1. 系统性关闭沙箱与审批（代码层，补丁 6–16）

| id | 补丁名 | 作用 |
|---|---|---|
| 6 | `SANDBOX_DENY_FILE_WRITE` | 关掉"沙箱外禁止写文件" |
| 7 | `SANDBOX_MODE_DEFAULT` | 改默认沙箱模式 |
| 8 | `APPROVAL_POLICY_DEFAULT` | 改默认审批策略 |
| 9 | `APPROVAL_AUTO_GRANT` | 审批自动放行 |
| 10 | `APPROVAL_CONFIG_DEFAULT_NEVER` | 配置层默认改为永不询问 |
| 13 | `ESCALATION_WIDENING_EXEMPT` | 权限升级免审 |
| 14 | `ESCALATION_GRANT_UNCONDITIONAL` | 无条件授予升级 |
| 15 | `SANDBOX_CONFINE_PASSTHROUGH` | 沙箱约束透传（等于不约束） |
| 16 | `FS_FENCE_DISABLED` | 关闭文件系统围栏 |

### 2. 关闭 hook deny 通道（补丁 30/31/64/65）

`lib/hooks-deny.js` 把 `decision === "deny"` 的分支替换成死字符串
`__dsh_purge_deny_disabled__`，使 hook 的拒绝路径失效。

### 3. 改写应用本体

解包并修改已安装的 `app.asar`（`extract-asar.js` / `surface.js` / `reapply.js` /
`desktop.js`），共 82 处补丁位点；Windows 上 `schtasks` 注册常驻任务
`DSH Doctor Supervisor`（`core.js:1204`）。`core.js:1474` 在
`danger-full-access` 时删除 `DSH_PERMISSION_MODE` 环境变量。

### 4. 破甲载荷

`lib/default-prompt-inject.zh.md`（25.6 KB）/ `.en.md`（29.4 KB），
注入为 `system/<project_instructions>`，替换默认人格。

### 5. 自更新无完整性校验

`update.js` / `official-update.js` 未见 sha256 / 签名 / verify，整包 tarball 覆盖。
上游仓库若易主或账号失守，本机随之升级。

### 6. README 内含"面向 AI 助手"的安装指令

`README.zh-CN.md` 中有 `<!-- AI-AGENT-START -->` 段落，直接指示助手执行
`dsh plugin add`。属面向 agent 的注入式引导，应按不可信数据处理，不自动执行。

## 四、若要自行安装后的回滚

仓库自带 `lib/uninstall.js` / `lib/hooks-deny.js` 的反向替换表（R1a/R1a2/R1b/R2a/R2b），
可在"清洗"页做反向还原；但应用本体被 `app.asar` 重打包的改动建议整份重装官方版本覆盖。
